# Getting Started

This guide takes you from nothing to a working Microsoft 365 configuration that
uses the composite resources of DscConfig.M365. It covers the two ways to work
with this module: consuming it through Microsoft365DscWorkshop, and building it
from source when you want to change or extend it.

## Which path do I need

- **Configure a Microsoft 365 tenant** — follow
  [Consume the module through Microsoft365DscWorkshop](#consume-the-module-through-microsoft365dscworkshop).
- **Add a resource, fix a bug, or release the module** — follow
  [Build the module from source](#build-the-module-from-source).

DscConfig.M365 is the middle layer of a three-tier solution and is **not**
installed or used standalone:

1. [Microsoft365DSC](https://github.com/microsoft/Microsoft365DSC) — the DSC
   resources that talk to the Microsoft 365 APIs.
1. **DscConfig.M365** — composite resources, prefixed with `c`, that wrap those
   resources and take many instances through a single `Items` array.
1. [Microsoft365DscWorkshop](https://github.com/dsccommunity/Microsoft365DscWorkshop)
   — the deployment framework that holds the configuration data, compiles it and
   enacts it against your tenants.

## Prerequisites

- Windows. The build compiles MOF files and queries `Get-DscResource` against
  Microsoft365DSC.
- PowerShell 7 or later. The `TestPowerShell7` build task fails the build on
  Windows PowerShell 5.1.
- Local administrator rights on the machine that runs the build.
- Internet access to the PowerShell Gallery so the build can restore
  dependencies into `output/RequiredModules`.
- For an actual deployment: a Microsoft 365 tenant and an app registration or
  managed identity with permission to configure it. Microsoft365DscWorkshop
  creates those for you.

## Consume the module through Microsoft365DscWorkshop

This is the supported way to use the composite resources. Microsoft365DscWorkshop
already declares DscConfig.M365 as a dependency, so you never install this module
by hand.

### Clone the workshop and restore its dependencies

```powershell
git clone https://github.com/dsccommunity/Microsoft365DscWorkshop.git
cd Microsoft365DscWorkshop
.\build.ps1 -UseModuleFast -ResolveDependency
```

The first run takes a while because it downloads Microsoft365DSC and its many
Graph, Exchange, Teams and PnP dependencies. It restores DscConfig.M365 to
`output\RequiredModules\DscConfig.M365`.

> **Note:** The workshop's own
> [getting started guide][workshop-getting-started] covers the Azure DevOps
> project, the app registrations and the build agents. Follow it for a complete
> environment; this page only covers the parts that concern DscConfig.M365.

### Confirm how the module is wired in

Two files in the workshop reference this module.

`RequiredModules.psd1` pins the version that is restored:

```powershell
# Composites
'DscConfig.M365' = '0.7.0-preview0001'
'DscConfig.Demo' = 'latest'
```

`build.yaml` registers it as a composite resource module so the DSC pipeline
imports it and packages it with the artifacts:

```yaml
Sampler.DscPipeline:
  DscCompositeResourceModules:
  - PSDesiredStateConfiguration
  - DscConfig.M365
  - DscConfig.Demo
```

To move to a newer release of DscConfig.M365, change the pin in
`RequiredModules.psd1` and restore again.

### Point the workshop at your tenant

Put your tenant details into `source\Global\Azure.yml` and remove the
environments you do not need:

```yaml
Environments:
  Dev:
    AzTenantId: b246c1af-87ab-41d8-9812-83cd5ff534cb
    AzTenantName: contoso.onmicrosoft.com
    AzSubscriptionId: 9522bd96-d34f-4910-9667-0517ab5dc595
    Identities:
    - Name: M365DscLcmApplication
      ApplicationId: <AutoGeneratedLater>
      CertificateThumbprint: <AutoGeneratedLater>
```

The workshop's `lab\10 Setup App Registrations.ps1` script fills in the
`<AutoGeneratedLater>` placeholders.

### Write your first composite resource configuration

Configuration data lives in `source\` as a
[Datum](https://github.com/gaelcolas/Datum) hierarchy. Every composite resource
gets its own YAML file, and the **file name is the composite resource name**.

To manage Entra ID groups, edit
`source\1-AllTenantsConfig\AzureAd\cAADGroup.yml`:

```yaml
Items:
  - MailNickname: Marketing
    DisplayName: Marketing
    Description: Marketing department
    MailEnabled: false
    SecurityEnabled: true
    Ensure: Present
  - MailNickname: Sales
    DisplayName: Sales
    Description: Sales department
    MailEnabled: false
    SecurityEnabled: true
    Ensure: Present
```

The content of the file is exactly the parameter set of the composite resource.
`Items` is the array of Microsoft365DSC resource instances; the connection
parameters may be set once for the whole file instead of per item. See
[Usage](Usage.md) for the full parameter list.

Then make sure the composite resource is enacted by listing it in the
`Configurations.yml` of the same folder:

```yaml
- cAADNamedLocationPolicy
- cAADGroup
- cAADAuthorizationPolicy
- cAADGroupsSettings
- cAADSecurityDefaults
```

### Build and review the result

```powershell
.\build.ps1
```

Inspect the artifacts before you enact anything:

- `output\RSOP` — the resolved configuration data per node. This is the fastest
  way to confirm that your values survived the Datum merge.
- `output\MOF` — the compiled configuration that the Local Configuration Manager
  will enact.

### Enact the configuration

Commit and push your change and let the workshop's `M365DSC push` pipeline apply
it. The pipeline builds the artifacts, enacts them against the tenant and then
re-tests the tenant against the desired state.

## Build the module from source

Use this path when you want to add a resource to the supported set, fix the code
generator or cut a release.

### Clone and build

```powershell
git clone https://github.com/dsccommunity/DscConfig.M365.git
cd DscConfig.M365
.\build.ps1 -ResolveDependency -Tasks build
```

The build does three things:

1. `Create_Dsc_Resource_Yaml_File` writes `source\DSCResources.yml`, the list of
   Microsoft365DSC resources to wrap and whether each becomes a `Scalar` or an
   `Array` composite resource.
1. `Create_Dsc_Composite_Resources` deletes and recreates `source\DSCResources`
   with one folder per composite resource.
1. ModuleBuilder packages the result into
   `output\Module\DscConfig.M365\<version>`.

> **Warning:** `source\DSCResources`, `source\DSCResources.yml` and `output` are
> generated and excluded by `.gitignore`. Never hand-edit files there, because
> the next build discards them.

### Run the tests

```powershell
.\build.ps1 -Tasks test
```

The unit tests compile every generated composite resource against the sample
configuration data in `tests\Unit\DSCResources\Assets\Config` and assert that
each resulting MOF file in `output\MOF` carries Azure connection data.

### Inspect what was generated

```powershell
Get-DscResource -Module DscConfig.M365
Get-Content .\source\DSCResources\cAADGroup\cAADGroup.schema.psm1
```

Each generated `*.schema.psm1` keeps the syntax block of the underlying
Microsoft365DSC resource in a comment, so the available properties stay
discoverable without leaving the file.

### Add a resource to the supported set

The set of generated composite resources is driven by the YAML assets in
`tests\Unit\DSCResources\Assets\Config`. Each file is named after the composite
resource it exercises.

1. Create `tests\Unit\DSCResources\Assets\Config\c<ResourceName>.yml` with
   sample configuration data for the Microsoft365DSC resource.
1. Run `.\build.ps1 -Tasks build,test`.
1. Confirm that `output\MOF\localhost_c<ResourceName>.mof` was produced.

If the folder is empty, the build falls back to generating a composite resource
for every Microsoft365DSC resource.

### Update the Microsoft365DSC version

1. Change the `Microsoft365DSC` pin in `RequiredModules.psd1`.
1. Start a new PowerShell session so no module handles stay open.
1. Delete `output` and run `.\build.ps1 -ResolveDependency -Tasks build,test`.
1. Fix any test assets that no longer match the upstream schemas.
1. Record the change in `CHANGELOG.md` under `[Unreleased]`.

## Troubleshooting

**The build stops in `TestPowerShell7`.**
You are on Windows PowerShell 5.1. Run the build in PowerShell 7 or later.

**`Get-DscResource` returns fewer resources than there are folders in
`source\DSCResources`.**
One generated composite resource cannot be loaded, usually because of an
unresolvable parameter type. Import the `*.schema.psm1` directly to see the
error.

**A test fails with an invalid property.**
The Microsoft365DSC schema changed. Align the asset in
`tests\Unit\DSCResources\Assets\Config` with the new schema.

**Microsoft365DscWorkshop cannot find `DscConfig.M365`.**
`RequiredModules.psd1` pins a version that is not published on the PowerShell
Gallery. The restore skips it silently. Pin a published version.

**A value you set in YAML does not appear in the MOF file.**
The Datum merge dropped it. Check `output\RSOP` and the `lookup_options` in
`source\Datum.yml`.
